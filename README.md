Задание 1 Модуль 1-4

1. Описание проекта

 UniversityApi — REST Web API для управления студентами, преподавателями, учебными курсами и записями студентов на курсы.

Проект разработан в рамках практической работы по дисциплине CSE5032 «Разработка веб-сервисов».

API позволяет создавать, получать, изменять и удалять данные, проверять корректность входных данных, обрабатывать ошибки и предотвращать повторную запись студента на один и тот же курс.

2. Цель работы

Цель работы — разработать REST Web API на ASP.NET Core с использованием PostgreSQL и Entity Framework Core, применив изученные принципы проектирования веб-сервисов.

В проекте реализованы:

REST-архитектура и маршрутизация контроллеров;

работа с базой данных через Entity Framework Core;

Repository Pattern;

Dependency Injection;

DTO для передачи данных;

AutoMapper для преобразования объектов;

единый формат ответов API;

валидация данных;

централизованная обработка исключений;

логирование операций;

Swagger / OpenAPI для проверки эндпоинтов.

4. Основные сущности

Student

Содержит информацию о студенте:

Id — идентификатор;

FirstName — имя;

LastName — фамилия;

Email — адрес электронной почты;

BirthDate — дата рождения;

CreatedAt — дата создания записи.

Teacher

Содержит информацию о преподавателе:

Id — идентификатор;

FirstName — имя;

LastName — фамилия;

Email — адрес электронной почты;

Department — кафедра или подразделение.

Course

Содержит информацию об учебном курсе:

Id — идентификатор;

Name — название курса;

Description — описание;

Credits — количество кредитов;

TeacherId — идентификатор преподавателя;

CreatedAt — дата создания записи.

Каждый курс связан с преподавателем.

Enrollment

Представляет запись студента на учебный курс:

Id — идентификатор;

StudentId — идентификатор студента;

CourseId — идентификатор курса;

EnrollmentDate — дата зачисления;

Grade — оценка.

Один студент может быть записан на несколько курсов. Один курс может иметь нескольких студентов.

7. Работа с базой данных

Для хранения данных используется PostgreSQL. Доступ к базе осуществляется с помощью Entity Framework Core и ApplicationDbContext.

Для конфигурации моделей применяются два подхода:

Data Annotations — атрибуты [Required], [StringLength], [EmailAddress] и [Range].

Fluent API — настройка связей, внешних ключей, уникальных индексов, правил удаления и точности числовых значений в ApplicationDbContext.

Настроены:

первичные ключи сущностей;

связи между студентами, преподавателями, курсами и зачислениями;

уникальность email студентов и преподавателей;

запрет повторной записи одного студента на один курс;

ограничения на значения некоторых полей.

Настройка подключения

Строка подключения хранится в конфигурации приложения. Перед запуском необходимо указать параметры своей базы PostgreSQL.

Пример формата строки подключения:

{
  "ConnectionStrings": {
    "DefaultConnection": "Host=localhost;Port=5432;Database=university_course_db;Username=YOUR_USERNAME;Password=YOUR_PASSWORD"
  }
}

Вместо YOUR_USERNAME и YOUR_PASSWORD необходимо указать собственные учётные данные.

Важно: не следует публиковать реальные пароли в Git или README. Для локальной разработки можно использовать пользовательские секреты или переменные окружения.

8. Запуск приложения

Шаг 1. Подготовить окружение

Необходимо установить:

.NET SDK 9;

PostgreSQL;

IDE или редактор для работы с C#.

Шаг 2. Настроить базу данных

Создать базу university_course_db либо использовать уже созданную базу. Проверить строку подключения в конфигурации приложения.

Если таблицы ещё не созданы, необходимо применить имеющиеся миграции Entity Framework Core или подготовленный SQL-скрипт.

Шаг 3. Восстановить зависимости

В терминале из каталога проекта выполнить:

dotnet restore

Шаг 4. Запустить приложение

dotnet run

После запуска проверить адрес, указанный в выводе приложения. В ходе тестирования Swagger использовался по адресу:

http://localhost:5000/swagger

Если приложение запустилось на другом порту, следует открыть адрес, указанный в консоли.

10. Валидация и бизнес-правила

В проекте используются атрибуты валидации, в том числе:

[Required] — обязательность поля;

[EmailAddress] — проверка формата email;

[StringLength] — ограничение длины строк;

[Range] — ограничение допустимых числовых значений.

При создании зачисления API проверяет существование студента и курса. Повторное зачисление на тот же курс запрещается.

Уникальные индексы базы данных дополнительно защищают от дублирования email и повторных записей студента на курс.

11. Формат ответов и обработка ошибок

Для формирования ответов используется универсальный класс ReturnResult<T>.

Он содержит следующие поля:

StatusCode;

IsSuccess;

Result;

ErrorCode;

ErrorMessage;

TraceId.

При обработке запросов используются соответствующие HTTP-коды, в том числе 200, 201, 400, 404, 409 и 500.

Централизованная обработка исключений реализована в ExceptionHandlingMiddleware. Необработанные исключения записываются в лог, а клиент получает общее сообщение об ошибке без раскрытия внутренних технических деталей.
